\section{Introduction}

The gap between ``I read the transformer paper'' \citep{vaswani2017attention}
and ``I understand how a
modern LLM is actually built, trained, aligned, and served'' has widened
dramatically. A 2025-era system is not a transformer: it is latent-compressed
attention over a paged KV cache, sparse experts balanced without auxiliary
losses, extra prediction heads that double as speculative drafts, a
preference-optimization and verifiable-reward RL pipeline, and a continuous-%
batching server---each the subject of its own paper, none of them teachable in
isolation.

Existing educational resources each cover one leg
(\S\ref{sec:related}): nanoGPT and Raschka's book cover pre-training, the
Annotated Transformer and labml.ai cover single-paper architecture, Spinning
Up covers deep RL, and TinyTorch covers ML-systems foundations
\citep{tinytorch2026}. A learner who wants the \emph{connected}
story---why mid-training exists, how MTP heads become a serving speedup, why
the KV cache dictates attention design---must stitch it together from a dozen
sources with incompatible codebases.

BabyWhale closes this gap with one design decision: \textbf{a single
model's biography is the curriculum} (Figure~\ref{fig:lifecycle}). The same
checkpoint is born (architecture), learns to read (pre-training), specializes
(mid-training), learns to behave (SFT, DPO), learns to reason (GRPO with a
code sandbox), is compressed (FP4), goes to work (paged KV, speculative
decoding, continuous batching), and is judged (bits-per-byte, pass@1,
long-context retrieval)---all on consumer Apple-Silicon hardware, in minutes
per stage.

\paragraph{Target audience and impact.} BabyWhale serves three groups:
(i)~\emph{self-learners and graduate students} who know basic deep learning
and want the modern LLM stack end-to-end rather than in slices;
(ii)~\emph{instructors}, since each module is self-contained and its labs
autograde with a plain \texttt{python} invocation---no grading
infrastructure; and (iii)~\emph{research engineers onboarding onto LLM
systems}, for whom the measured ablations double as a systems-intuition
reference. The platform choice multiplies the reach: the target machine is
the Mac that a large share of developers and students already use daily, and
MLX's ecosystem---\texttt{mlx-lm} and thousands of community-converted
open-weight models---means what is learned here
applies immediately to real models, not only to the course's own. The barrier
to adoption is a software install, not a cluster.

The second idea addresses a failure mode we first measured in ourselves:
\emph{educational prose drifts from the code it describes}. While auditing our
own drafts against the implementation we found and fixed eight confidently
wrong explanations---a mis-stated gating function, a wrong loss attribution,
an inverted masking claim (\S\ref{sec:eval}). BabyWhale therefore treats
pedagogy as a tested artifact, through three mechanisms we collectively call
\emph{machine-checked courseware}: exercises graded by functional equivalence
against the maintained implementation, displayed code guarded by tests that
fail on drift, and quantitative claims coupled to the commands that
regenerate them (\S\ref{sec:course}).

\paragraph{Contributions.} (1)~A curriculum design---the model biography---%
that makes the \emph{connected} lifecycle, rather than any single stage, the
object of study; (2)~machine-checked courseware, a methodology for keeping
teaching material consistent with a living system, which transfers to any
documented software; (3)~an open implementation with measured evidence: a
trained ablation ladder over the curriculum's architecture presets, staged
evaluations of a checkpoint lineage, and integrity checks that run in public
CI (\S\ref{sec:eval}).
